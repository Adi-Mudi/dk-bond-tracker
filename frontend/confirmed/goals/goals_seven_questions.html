Q1 DATA —

What data does it show?

DATA CONTRACT
•
Form inputs (EXACTLY 4): goal name · start date · end date · amount ₹ monthly → target + total months auto-derive (read-only). Nothing else typed (no Saved, Note, invested — locked base).
•
Field → source map: goal name/dates/amount → local goals store (user at create/edit) · Saved so far → store (migrated/derived) · card dates + months-left → derived from dates (store) · pace ₹/mo → derived (plan ÷ months) · status pill + months signal + urgency tier → derived (schedule vs invested) · tab counts GOALS (n)/FORM (n) → derived (store) · INVESTED column → PORTFOLIO purchase dates (Watchlist → Move to Portfolio) · RETURNS column → PORTFOLIO bond interest · linked-bond name/ISIN/rate/total-interest → PORTFOLIO holdings + bond master · derivation Month/Target/Running Total → derived (schedule math) · missed-banner months → derived (schedule vs invested) · UI copy (labels/buttons) → hardcoded design strings.
•
Not displayed: progress % text is NEVER shown (psychology rule AC2) — only the unlabelled progress rail; target amounts appear only inside derivation math + totals row.
•
Locked-base sections covered: 5-column Derivation Table (Month · Target · Invested · Returns · Running Total-dim) · static accent totals row · missed-signal detail banner · linked-bond rows (name · ISIN · rate · total interest received).

What can the user do?

INTERACTIVITY

Navigate: goal card → Details (detail frame) · GOALS/FORM segmented tabs (list frame) · bottom nav (own back stack) · Back arrow + system edge-swipe return (form/detail → list)
•
Detail management (top-bar ⋮ ONLY): Edit goal → prefilled form · Archive goal — NO Remove (locked; goals end via Achieved/Archived). No inline Goal Actions card exists (removed with old board).
•
Detail data actions: linked-bond row tap → bond detail page · derivation table scrolls (>24 months)
•
Shell app bar: Sync Ledger (manual refresh, G33) · Notifications · Change Theme · avatar
•
List extras: scroll-to-top (list >1 screen, G35) · error Retry (G31) · gestures: tap-only — no swipe-delete, no long-press, system edge = back

Q3 STATES —

All four + loading pattern

LIFE CYCLE
•
Working ✓: normal list/detail render · missed-signal banner + "N months missed" are WORKING business states (not errors)
•
Loading (pattern CHOSEN: SKELETON — layout known): list = goal-card skeletons · detail = Saved-card + derivation-table skeleton rows + linked-bonds skeleton · sync icon spins during G33 refresh · Save goal = inline button spinner + submit lock (spinner allowed — one-off submit, no layout to preview)
•
Empty ✓: list → "No goals yet — Create first goal" (G05) · detail linked section → empty state when0 holdings (G32/E12)
•
Error ✓ (G31): fetch/offline/save-failure → persistent specific message + Retry · entries preserved on failed save · never blank, never vanishing toast
•
Visibility states: archived/completed goals stay visible (dimmed, last, G36) — never silently hidden
•
Rule: never a spinner where a skeleton works (E15); spinner only for one-off submit/refresh

Q4 SCROLL —

Three answers

VIEWPORT BEHAVIOR
•
Load-more: SHOW-ALL chosen — goals list renders every goal in one scroll (personal lists are short); no pagination, no infinite scroll. Revisit only if a user passes ~30 goals (then Load-More, not infinite — footer stays reachable).
•
Sticky: top app bar + GOALS/FORM tabs pinned above the scroll viewport; bottom nav always fixed. Detail frame: fixed top bar (Back · title · ⋮) above the scroll; derivation table header row sticks inside table scroll; static totals row (tfoot) stays at table foot.
•
Scroll-to-top: floating control appears after1 screen down (G35) → smooth scroll to top · short list = never renders
•
Detail table: >24 months → vertical scroll + horizontal column scroll (Running Total visible via scroll) · static totals row remains reachable at foot
•
Layout flow: cards single column, consistent16px gaps (matches locked base)

Q5 RULES —

Hidden rules (written note)

BUSINESS LOGIC
•
Target formula (locked): target = Amount (₹ monthly) × total months (dates) — e.g. ₹35,000 ×22 = ₹7,70,000 plan; the detail totals row shows saved + invested + returns as the derived outcome (₹20,00,000). The old saved+growth formula is RETIRED with the dual-entry form.
•
Validation: all4 inputs required · goal name non-empty · end date > start date (reversed/equal → error, entries preserved) · amount ₹ >0 · submit lock on Save goal (one tap = one action)
•
Permissions: N/A — local-first roleless MVP (same as components note)
•
Psychology (G26): zero target amounts on cards/detail/stat surfaces (only derivation math shows totals) · months signal = exactly one, negative sticky until resolved
•
Ordering/visibility (G34/G36): soonest end-date first · Completed last dimmed · archived stay visible (dim) · zero-investment months still show returns (G21) · ₹ INR Indian grouping everywhere (FR12)
•
Preservation invariant: linked bonds never deleted with goal (watchlist pattern)
•
Removal removed from design (2026-11-27): no Remove option anywhere — goals end via Achieved (auto at 100%) or Archived; linked bonds / portfolio never touched by either
•
Urgency tier hierarchy: Behind > Due Soon > On Track > Completed (dim)

Q6 CONNECTION —

How it talks (written note)

INTEGRATION
•
Local endpoints (Flask): GET /goals (list) · POST /goals (create) · POST /goals/<id>/edit (update — POST-only) — /checkin and /delete RETIRED with locked base. Views: src/views/goals.py (goals_page, goals_edit).
•
Repository methods: src/goals.py list_goals(conn, today=None) · add_goal(...) · update_goal(conn, goal_id, name, target_amount, target_end_date, saved_amount=None) — local store CRUD (name/start/end/amount in → goal row out)
•
Derivation query: src/queries/summary.py goal_derived(conn) — takes the connection only → returns {goal_id: {invested, returns, bonds}} (invested from portfolio purchase dates, returns from bond interest, bonds = linked holdings); month rows composed by list_goals/edit views
•
Flutter side: local repository class (Essential5 boundary) — raw store access never in widgets · Dio wiring = contract phase (no remote API yet)
