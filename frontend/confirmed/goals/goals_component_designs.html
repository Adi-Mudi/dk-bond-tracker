Goals — Component Designs (7 questions each)

Every component on the Goals page — including sub-components nested inside larger ones — designed against the full checklist: 1 DATA · 2 ACTIONS · 3 STATES · 4 FEEDBACK · 5 RULES · 6 CONNECTION · 7 SCREENS, plus the gesture rules and nesting rule below. Rules that apply to every component global

GESTURE RULES (per component, must be stated): Goals page is tap-only — no destructive swipe anywhere (single accidental swipe must never act) · no long-press needed on this page (delete is gone; the only long-press in the app = typed-ISIN confirm, page-level) · any edge swipe = system back wins · horizontal scroll allowed ONLY inside the derivation table (component states it) · every gesture conflict listed in that component's ACTIONS row.
NESTING RULE: components nest — each level runs its own checklist. The page never talks to the database — only to its own components. Data flows: store/endpoint → page/repository → props down → components; events flow: component callback → page → repository. Nesting map: Goal Card(G2) ⊃ Months Signal(G3) + Status Pill(E13) + Progress Rail(E14) + Pace(E2-row) + Details(E8) · Linked Card(G9) ⊃ Linked Row(G10) ×n · Form(G5) ⊃ Text Inputs(E9)×4 + Readouts(G4) + Save(E8) · Detail ⊃ Saved Card(G7) + Derivation(G8 incl. totals G30) + Banner(E11 via G28) + Menu(E10).

Shared components 10

E1 · Top App Bar organism · shared

  • 1 DATA: title (page prop) · sync/bell/theme/avatar icons · notification badge count (page prop). Source: passed in — component fetches nothing.
  • 2 ACTIONS: tap sync → triggers page refresh (callback) · tap bell/theme/avatar → shell callbacks. No swipes; edge swipe here = system back (no conflict — icons are taps).
  • 3 STATES: working (idle) · loading (sync icon spins) · empty (badge hidden at0) · error (refresh failure surfaces as page G31 banner, not in bar) + scrolled/focused.
  • 4 FEEDBACK: sync tap → immediate spin ≤1s then stops (+ page skeleton runs) · badge appears/disappears instantly · no toasts from the bar itself.
  • 5 RULES: icon order fixed (sync · bell · theme · avatar) · badge count >9 → "9+" · every icon-button carries a Semantics action label.
  • 6 CONNECTION: receives via props + emits callbacks — no endpoint calls inside (nesting rule).
  • 7 SCREENS: full-width fixed top on every frame at412dp; title truncates with ellipsis; no tablet/desktop behavior (Compact-only).

FAB + (create) atom · reused kit

  • 1 DATA: none — icon-only.
  • 2 ACTIONS: tap → emits onCreate → page opens full-screen form (G03). No swipe/long-press; no conflict with edge zones (sits above bottom nav, inward).
  • 3 STATES: working (rest) · loading n/a · empty n/a (always available) · error n/a (failures live in form).
  • 4 FEEDBACK: press scale−6%/dim62% (E8 press spec) → form transition slides in400ms.
  • 5 RULES: one FAB per frame (list only) · SR label "Add goal".
  • 6 CONNECTION: callback only (onCreate).
  • 7 SCREENS: fixed bottom-right above nav at412dp; resizes not applicable (Compact-only).

E8 · Button atom · variant props

  • 1 DATA: label + variant(primary|secondary|ghost|destructive|link) + enabled/loading flags — all props.
  • 2 ACTIONS: tap → onPressed callback. No swipe/long-press/drag. Conflict: none (tap only); double-tap prevented by loading-lock.
  • 3 STATES: working(enabled/pressed) · loading(button spinner, disabled) · empty n/a · error n/a (parent shows errors).
  • 4 FEEDBACK: press −6% + dim62% (150ms) → release · loading = spinner in-button · result toast/confirm owned by PAGE (component only shows busy).
  • 5 RULES: verb+result label ≤4 words · disabled shows why nearby · never two primary buttons in one dialog · one tap = one action.
  • 6 CONNECTION: onPressed callback + label props — no data fetching.
  • 7 SCREENS: full-width inside forms at412dp · labels wrap, never clip.

E9 · Text Input atom · type variants

  • 1 DATA: value · label · helper · error text — all props (page owns state).
  • 2 ACTIONS: tap→focus · type · (date variant: tap calendar icon). No swipe/long-press. Conflict: none.
  • 3 STATES: working(filled/idle) · loading(date fetch variant n/a) · empty(valid pristine) · error(invalid → red border + icon + rule text).
  • 4 FEEDBACK: validation fires per timing (typing/blur/submit per E6) → error appears instantly below field, entries preserved · success silent.
  • 5 RULES: label states requirement, no asterisk · placeholder = realistic example · ₹ suffix on amounts (never $) · never placeholder-only.
  • 6 CONNECTION: value/onChanged props only — page writes store.
  • 7 SCREENS: full-width, helper/error below (wraps) ·412dp single column.

E10 · Overflow menu ⋮ molecule · shared

  • 1 DATA: items array prop — goals instantiation = [Edit goal, Archive goal] only.
  • 2 ACTIONS: tap ⋮ → open (immediate, no animation) · tap item → onSelect callback · tap-away or system back → close. Edge swipe = system back (wins, just closes menu).
  • 3 STATES: working(closed/open) · loading n/a · empty n/a (never empty) · error n/a.
  • 4 FEEDBACK: menu appears instantly · item tap → menu closes then page shows confirm/toast per action (Archive: confirmation dialog first — see G23).
  • 5 RULES: NO Remove item ever (locked) · destructive/lifecycle items route through confirmation before firing.
  • 6 CONNECTION: props + onSelect callback.
  • 7 SCREENS: anchored below trigger; long items scroll inside popup;412dp fine.

E11 · Banner molecule · shared

  • 1 DATA: variant(info|warning|error) + headline + body (+ optional Retry) — props from page (G28 missed-signal, G31 error).
  • 2 ACTIONS: optional tap Retry (error variant). No swipe. Conflict: none.
  • 3 STATES: working(info/warning shown) · loading(retry in-flight spinner in button) · empty(hidden — renders nothing) · error(error variant with Retry).
  • 4 FEEDBACK: Retry → spinner → dismiss or update · warning persists until underlying issue resolves (missed banner sticky).
  • 5 RULES: icon+text+colour (never colour alone) · missed-banner months named exactly (e.g. "Nov & Dec2026 missed before start").
  • 6 CONNECTION: receives content via props — page/repository talks to store.
  • 7 SCREENS: full-width block; body wraps at412dp.

E12 · Empty State organism · shared

  • 1 DATA: icon · headline · body · CTA label — props (goals: "No goals yet" / "Create first goal"; linked: empty-linked).
  • 2 ACTIONS: tap CTA → onCreate callback (page opens form). No other gestures.
  • 3 STATES: working n/a (it IS the empty state) · loading n/a (data arrived, zero rows) · empty(shown) · error n/a (errors use E11).
  • 4 FEEDBACK: press feedback on CTA → form opens.
  • 5 RULES: never bare "No data" — always what belongs + how to add · hidden when rows exist.
  • 6 CONNECTION: props only.
  • 7 SCREENS: centered vertical stack, padding scales; text wraps.

E13 · Status Pill atom · shared

  • 1 DATA: tier (Behind|Due Soon|On Track|Completed) — derived value passed by page.
  • 2 ACTIONS: NONE — inert (no tap, no swipe). Explicitly not interactive; no conflicts.
  • 3 STATES: working(4 tiers) · loading(placeholder tier) · empty n/a · error n/a.
  • 4 FEEDBACK: n/a — no action exists.
  • 5 RULES: colour ALWAYS paired with text · hierarchy Behind > Due Soon > On Track > Completed(dim).
  • 6 CONNECTION: prop only.
  • 7 SCREENS: inline chip; text wraps at narrow widths.

E14 · Progress Rail atom · shared

  • 1 DATA: percent0–100 (derived, unlabelled) — prop. NO numbers or targets displayed.
  • 2 ACTIONS: NONE — inert. No conflicts.
  • 3 STATES: working(fill) · loading(skeleton rail) · empty(0%) · error n/a.
  • 4 FEEDBACK: n/a (updates silently with data).
  • 5 RULES: never shows % text or target (psychology) · clamps0–100.
  • 6 CONNECTION: prop only.
  • 7 SCREENS: full-width bar; height fixed16dp.

G2 · Goal Card organism · new

  • 2 ACTIONS: tap Details → detail (callback) · whole card tap = same as Details (single action). No swipe (delete banned), no long-press. Conflict: none — rail/pill/signal are inert children.
  • 3 STATES: working(on-plan/missed) · loading(skeleton card) · empty(n/a — E12 instead) · error(page G31 strip above list, card not rendered).

G4 · Auto Readout Card molecule · new

G5 · Create / Edit Form organism · new

  • 1 DATA:4 inputs (name · start · end · amount) + readouts(G4) — values held in form state (component-local), persisted via page on save; Edit mode = prefilled props (G27).
  • 2 ACTIONS: type fields · pick dates (calendar) · tap Save goal. No swipe (sheet-dismiss n/a — full-screen page · system back = leave with draft preserved per E6). Conflict: none.
  • 3 STATES: working(filling) · loading(submitting: save spinner+lock) · empty(pristine) · error(validation inline + save-failure persistent G31-style with entries preserved).
  • 4 FEEDBACK: validation appears instantly on blur/submit (icon+text, entries kept) · save tap → button locks + spinner → success toast "Goal saved" (E14 specific) → back to list · save-failure → persistent error + Retry, values intact.
  • 5 RULES: exactly4 inputs, all required · end > start · amount >0 ₹ · no asterisks · submit lock (one tap = one action) · no Saved/Note/invested fields.
  • 6 CONNECTION: form does NOT talk to the database — emits onSave(values) → page → repository (list_goals/add/update). Nesting rule.
  • 7 SCREENS: full-screen frame; inputs full-width stacked at412dp; readouts below inputs; save button pinned bottom (thumb zone).
