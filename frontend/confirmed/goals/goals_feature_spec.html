1 · Summary overview

  • Feature: Goals page — create savings goals, track them automatically against the portfolio, and review month-wise progress.
  • Owner: PM (design) · Developer (build) · Status: design LOCKED (base screen 6e072293…), implementation not started
  • Why: bond investors need a clean way to set a savings target and see — without manual entry — how much they invested, what the bonds returned, and whether they are on plan.
  • Success metrics: time-to-first-goal <2 min ·100% of invested/returns shown without typing · months-signal visible on every card · zero manual bookkeeping.

2 · Problem & goals why

  • Problem: tracking a savings goal today means spreadsheets; investment and interest data already exist in the portfolio but are not surfaced per goal; big target numbers demotivate (psychology finding).
  • Goal: one page where the user enters FOUR things once, and everything else — months, target, invested, returns, totals — is calculated.
  • Non-goals (out of scope): iOS · tablet/desktop reflow (post-MVP) · manual check-in / Save draft (removed — data is auto) · Remove/delete of goals (Archive only) · dynamic theming (4 locked static themes) · backend redesign (contract phase).

3 · Users & user stories 5

As a salaried saver, I want to set a goal with monthly amount and dates so that the app tells me the total months and target automatically.→ G13–G15 · clean form with auto readouts
As a bond investor, I want my goal to show month-wise invested and returns from my portfolio so that I see real progress without entering anything.→ G19–G21 · derivation table, auto columns
As a user who missed a month, I want a clear red "N months missed" signal that stays until resolved so that I know exactly what to fix.→ G08 · months signal, negative precedence
As a reviewer, I want a single colored totals row (months · target · invested · returns) so that I can verify the plan at a glance.→ G19 · static accent totals row
As a user, I want to tap a linked bond and see its detail so that I can check how much total interest it has delivered.→ G22 · linked bond rows with interest totals

5 · Acceptance criteria Given/When/Then

AC1 · Auto-calc: Given the form has dates Jan2027→Oct2028 and amount ₹50,000, When the user views the readouts, Then total months shows "22" and target shows "₹11,00,000" with no further input.
AC2 · No target on cards: Given any goal list, When scanning cards, Then no target amount or percent-of-target text appears anywhere — only Saved ₹ and the months signal.
AC3 · Missed signal: Given a goal with missed months, Then a red "N months missed" shows and takes precedence over any green signal until resolved.
AC4 · Auto columns: Given a holding was moved to portfolio with purchase date in month M, Then month M's INVESTED cell fills automatically; returns fill from bond interest even when invested is zero.
AC5 · Totals row: Given the table renders, Then one static accent totals row exists with months · target · invested · returns — and it is the ONLY coloured row (data rows plain).
AC6 · Interest totals: Given linked bonds, Then each row shows total interest received (e.g. ₹1,42,500) — never a per-month figure — and tapping opens the bond detail.
AC7 · No Remove: Given any goal state, Then no Remove/delete affordance exists; only Edit and Archive.
AC8 · TalkBack: Given TalkBack on, Then every control announces a label; contrast ≥4.5:1 on all text (Mandatory Bar M1/M2/M5).

6 · Non-functional requirements NFR

  • Accessibility: WCAG2.2 AA target ·48dp touch targets · TalkBack labels · text scales to200% · colour never alone (Mandatory Bar M1–M18).
  • Performance: skeleton for list load · local-first reads (goals store) · derivation computed <100ms for24 rows.
  • Reliability: failure matrix applies (offline/timeout/save-error keep entries, never blank) — Essential5/15.
  • Privacy: no personal identifiers in bonds.db; goals data stays local (Secure Storage rules).
  • Platform: Android-only, Compact (412dp) primary; Material idiom; Flutter implementation from locked design.

8 · Data model & connections contract-phase

  • Goals store (local): name, start/end, amount, saved, status (active/achieved/archived) — CRUD via local repository (Essential5 boundary).
  • Portfolio origin (single source): invested ← purchase dates of goal-linked holdings; returns ← bond interest; linked bonds ← portfolio holdings. Goals page never recalculates holdings itself.
  • Bond master: ISIN → rating/coupon metadata for linked rows (repository ↔ database contract = separate phase).
  • API: none on this page (local-first); future sync = contract phase (Dio, timeouts, failure matrix ready in Essential5).

9 · Edge cases & error handling 7

  • Zero goals → empty state + CTA (never blank).
  • Missed months → red signal persists; pace banner design pending (open item).
  • Returns without investment in a month → returns still shown (motivation rule).
  • Dates reversed / equal → validation error, entries preserved.
  • Save failure → error stays visible, form data kept, retry.
  • Goal achieved → auto state change; archive available anytime; no delete.
  • Portfolio holding removed later → linked-bond row disappears; totals recompute (never negative history).
