Q1 DATA — What data does it show?

Data Contract
  • • Fields: company, ISIN, yield %, payout cycle, broker, invested amounts, unit counts, status pills, WATCHING/LEDGER counts
  • • Source: local bonds.db via repository (SSOT) · ISIN facts from NSDL/BSE fetch · counts derived from cache
02

Q2 ACTIONS — What can the user do?

Interactivity
  • • FAB+ → Add Bond form · ISIN Fetch · Save to Watchlist
  • • Row: Move to Portfolio (qty/amount/date/broker ref) · Details → detail screen
  • • Detail: ⋮ overflow → Remove (type ISIN + hold 2s) · alerts: Read Advisory / Dismiss
  • • Navigation: Tabs + bottom nav navigation
03

Q3 STATES — all four + loading pattern

Life Cycle
  • • Working ✓ · Loading = SKELETON for ledger rows, SPINNER for ISIN Fetch ("Checking")
  • • Empty ✓ "No bonds yet — Add first bond" · Error ✓ offline copy + duplicate-ISIN banner
  • • Rule: skeleton never replaced by spinner when layout is known
04

Q4 SCROLL — three answers

Viewport Behavior
  • • Load more: show-all + scroll-to-top at MVP scale (Load More when >100 rows)
  • • Sticky: top bar always + ADD FORM|LEDGER tabs ✓ designed
  • • Scroll-to-top: TOP button after one screen of content
05

Q5 RULES — hidden rules (written note)

Business Logic
  • • ISIN 12 chars · duplicate active ISIN blocked (same company) · credit day 1–31
  • • Remove: exact ISIN + hold 2s · never on-card delete · held positions never deleted here
  • • TDS never on principal · one name per concept (Move to Portfolio)

Q6 CONNECTION — how it talks (written note)

Integration
  • • ISIN lookup → NSDL/BSE (4 states: Found/Checking/Offline/Not Found)
  • • Save/Move → local repository write · Alerts ← alerts.py
  • • Dio wiring = contract phase (one instance, interceptor gate)
