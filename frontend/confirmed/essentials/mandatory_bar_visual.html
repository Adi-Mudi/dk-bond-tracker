M1

Touch target — the invisible tap box (48dp)

MATERIAL3

Every tappable thing needs an invisible hit area of at least 48×48dp — not just the icon you see. A tiny visible icon still needs a big invisible box around it, or people (especially thumbs) miss it. Below: the red one is too small (26dp — high miss rate), the green one is correct (48dp).

M5

TalkBack label — what the screen "says" out loud

MATERIAL3

TalkBack is Android's screen reader: a blind user swipes and it reads each element aloud. It reads the element's label, not the picture. An icon button with no label is announced as just "button" — useless. With a label it says "Notifications, double tap to activate". The dashed ring = TalkBack's focus.

✗ No label
TalkBack announces: "button"
✓ Label set
TalkBack announces: "Notifications, double tap to activate"
Rule: every interactive element has a spoken label (Flutter Semantics); test the whole flow with TalkBack on a real phone. In our app: Essential7, sync/bell/theme/avatar/⋮/FAB icons.
M2

Contrast — text must stand out (4.5:1)

WCAG 2.2 AA

Contrast = how much brighter text is than its background, as a ratio. Body text needs4.5:1; "large text" gets the looser 3:1 — and WCAG defines large precisely as ≥24px regular or ≥18.67px bold (not just any bold). Light grey on white usually fails — it looks "clean" but is unreadable in sunlight or for low-vision users.

M3

Never colour alone — pair it with text (and icon)

WCAG · HIG ref

About1 in12 men can't tell red from green. If "missed month" is only a red dot, they see nothing. Colour must always be paired with words (and an icon for speed).

M10

Reduce Motion — respect the OS switch

MATERIAL3

Android has a system setting "Remove animations" (some users get motion sickness; some need it). When it's on, the app must swap animations for instant/fade states instead of moving things around.

Animations ON (default)
Sheet slides up · button scales on press · numbers flash
"Remove animations" ON
Sheet fades in (no slide) · press = colour change only · no flash
Rule: read the OS setting; replace motion with fades/state changes. In our app: Essential8 + Essential7.
M7

Safe areas — don't draw under system bars

MATERIAL3

Android phones have a status bar on top (clock/battery) and a gesture bar at the bottom. Content must respect these insets (edge-to-edge is enforced on new Android) — or your header hides under the clock and your nav sits under the home gesture.

M8

Modals must always have a way out

MATERIAL3 · HIG ref

A bottom sheet or dialog that the user cannot close traps them (a real store-rejection pattern). Every overlay needs a clear exit: an X, a Cancel, a scrim tap, or the system back gesture.

M13/M15

Thumb zone & real-device testing

INDUSTRY · NN/g

People hold phones with one thumb. The bottom half is easy to reach; the top corners are a stretch. Primary actions (FAB, tabs, main buttons) belong in the reachable arc — and rules only count if tested on a real phone in a real hand, not a desktop preview.

M17

Icons must announce themselves

MATERIAL3

Icons are pictures — TalkBack can't see them. Every meaningful icon needs a label (Material Symbols ship with names; we still declare them). Decorative-only icons are hidden from TalkBack so they don't add noise.

✗ silentno label attached
✓ "Notifications"label set
◌ decorativehidden from TalkBack
Rule: meaningful icon = label; decorative icon = excluded from a11y tree. Use Material Symbols (our icon table in Essential3). In our app: sync/bell/theme/avatar/eye/⋮/chevrons/FAB.
M11

WCAG2.2 AA — the conformance target (POUR)

WCAG 2.2 AA

Our written bar: every screen conforms to WCAG2.2 Level AA (the55 testable A+AA criteria — the level accessibility laws reference). Four principles:

Perceivablecontrast, text alternatives, colour-not-alone, scaling
Operabletargets, keyboard/focus, gestures, timing
Understandableclear labels, predictable behaviour, error help
Robustworks with TalkBack, works at200% text
Rule: design + element DoD + page checklist all check against AA. In our app: this file is the visual reference; rules live in app_essentials § Mandatory bar.
