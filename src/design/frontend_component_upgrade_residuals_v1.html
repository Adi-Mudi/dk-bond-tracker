Colour rule (proposed for #264)

SeverityLeft barMeaning
danger■ redmoney already missed
due_today■ amberact today
warn■ ambersomething changed
reminder■ blueheads-up, no action yet
maturity_soon■ teal proposedtime is running out — plan, don't panic
Why teal: red and amber are already taken by money states, blue by reminders, green by success — maturity is a time state, not a money state, so it gets its own calm signal. Alternatives considered: purple (reads decorative next to this palette) and reusing amber (indistinguishable from due_today). Code note: theme.css has sev-reminder and an unused sev-info, but no sev-maturity_soon — one class + these tokens completes the five.

#261 D6 · In-app confirm dialog (still pending)

One dialog component replaces every browser confirm() — identical on Android and web. Press the button to see it:

Move Welspun Aunta-Simaria to portfolio?

This starts recording payments. The bond leaves your watchlist.

Dialog rules

  • Title states the action, one sentence of consequence
  • Right button repeats the verb on the button — never “OK”
  • One filled button; Cancel is a text button
  • Destructive uses the danger fill; ordinary moves use primary
  • Same component web + Android (kills the mismatch #261 problem 1)
D6 asks you yes/no — the mockup section 7 recommendation stands: yes, so both platforms confirm the same way.
