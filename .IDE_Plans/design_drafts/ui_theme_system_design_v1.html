1. Theme token contract — the exact values implementation ships

Every color in the app becomes one of these tokens. Light is the default block; Dark overrides via [data-theme="dark"]; System = no attribute + prefers-color-scheme; High Contrast via [data-theme="hc"]. Status colors use fg/bg PAIRS (text-safe in every theme). Chart colors are tokens too — the #1 thing that breaks in ad-hoc dark modes.

3. Theme switcher — exact behavior spec

  • Placement: header actions, after Notifications — same hover/focus dropdown pattern as the bell (no new UI pattern).
  • Four options: System (default) / Light / Dark / High Contrast. Active option shows a checkmark and tinted row; each row has a preview dot.
  • State: localStorage key dk_theme. System stores nothing and removes data-theme from <html>; the other three set data-theme="light|dark|hc".
  • No flash: tiny inline script in <head> (shown in this file's source, exactly as it will ship) applies the stored theme before first paint.
  • System dark: a @media (prefers-color-scheme: dark) block applies the dark token set only when data-theme is absent — so an explicit Light choice is never overridden by the OS.
  • Native UI: <meta name="color-scheme"> + color-scheme on :root per theme — scrollbars, form controls and canvas follow the theme (this is why the current app's scrollbars stay white in a future dark theme otherwise).
  • Cross-tab sync: the storage event updates open tabs (community best practice; ~6 lines).
  • JS-disabled: app still works — defaults to System (light or dark per OS). Nothing breaks, only the override is unavailable.

4. Legend & accessibility contract

Status semantics (every theme)

Danger overdue / needs action
On-going active position
Completed finished position
Label text always present — color is reinforcement, never the only signal (WCAG 1.4.1). Completed uses bluish-green (Okabe-Ito family), not pure green, to stay distinct from Danger for red-green color-blind users.

Contrast commitments

• Body text and labels: minimum 4.5:1 against their surface (WCAG AA) in all four themes.
• Brand header: white on #1971c2 = 4.6:1 (current #4dabf7 fails at 2.2:1 — this is an intentional accessibility fix).
• Status fg colors sit on their own bg tint, checked as pairs per theme.
• HC theme: pure black on white, 2px borders, no shadows.

Fixed-light surfaces (by design)

• Monthly Print page: always light — printing dark backgrounds wastes ink and fails most printers.
• Share snapshot export (share.py): standalone HTML, always light for maximum recipient compatibility.
• Both keep their own local styles; they opt out of the theme system deliberately.

What themes do NOT change

• Layout, information architecture, route structure — zero change.
• Status computation rules (zero-amount paid renders as due, etc.).
• Privacy Mode, notifications, CSV export, print layout.
• Offline guarantee: no CDN, no fonts fetched, no libraries (test_tc76 stays green).

5. Change list vs current theme (FROM → TO)

  • FROM one hardcoded theme → TO token contract with 4 theme modes (Light / Dark / System / High Contrast).
  • FROM 171 hardcoded hex colors across 9 templates → TO every color reads a token (SVG charts included, via CSS classes instead of fill attributes).
  • FROM gray cards (#F1F3F5) on a gray page (#F8F9FA) — flat, no depth → TO soft dim canvas #F5F6F8 + pure white cards + hairline #D0D7DE borders + soft two-layer shadow (Notion/Linear/Carbon depth model: white breathes, canvas dims, shadow lifts).
  • FROM 2px near-black borders on every card → TO 1px hairline #d0d7de + soft shadow (2px black kept only in HC theme, where it belongs).
  • FROM solid pastel status chips with poor contrast (white on #ff922b = 2.2:1) → TO fg/bg pair chips passing 4.5:1 with visible labels.
  • FROM red/green status pair (color-blind trap) → TO vermillion / orange / bluish-green with labels + lightness separation.
  • FROM flat equal-weight cards → TO lead metric (Total Investment) emphasized — 2026 fintech hierarchy pattern; content order unchanged.
  • FROM white scrollbars/canvas in a dark OS → TO native UI follows the theme via color-scheme.
  • Test impact (declared): test_tc35 / test_tc36 / test_tc76 pin current hex values — they update to assert the token contract (stronger guard: catches any future hardcoded color outside the system). Grid cell semantics tests (tc01–tc05) untouched.
  • Files touched at implementation: src/templates/*.html (11 files), src/app.py (none needed — theme is client-side), src/share.py (untouched, stays light), tests/test_tc35 + test_tc36 + test_tc76 (token assertions).
